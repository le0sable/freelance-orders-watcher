# Freelance orders watcher

Следит за фриланс-биржами и присылает в Telegram новые заказы по выбранным нишам. Всё собранное
копится в базе SQLite (`market.db`), по которой потом удобно анализировать рынок.

Работает на GitHub Actions, поэтому компьютер можно выключать. Настраивается прямо из Telegram:
кнопками 👍/👎 под заказами и командами в чате с ботом.

## Как это работает

```
GitHub Actions (каждые 10 минут, запуск длится ~9 минут)
  │
  ├─ раз в 3 минуты ──► площадки ──► новые заказы ──► market.db
  │                                        │
  │                                        └─► фильтр ниш + оценка 🎯 ──► Telegram
  │
  └─ в паузах ──► команды и кнопки 👍/👎 из Telegram ──► settings.json, market.db
```

- **Запуск.** Расписание в `.github/workflows/notify.yml` стартует `notify.py --loop 540`.
  Если предыдущий запуск ещё идёт, следующий ждёт в очереди, поэтому запуски не пересекаются.
- **Хранение базы.** Между запусками `market.db` лежит в кэше GitHub Actions. В репозиторий она
  коммитится раз в 6 часов и сразу после команд или оценок из Telegram, вместе с `settings.json`.
- **Первый проход.** Если базы нет или площадка встречается впервые, её заказы только сохраняются,
  без уведомлений. Иначе пришла бы вся лента разом.

## Площадки

| Площадка | Как собирается | Бюджет | Отклики | Время публикации | Заказчик |
|---|---|---|---|---|---|
| Kwork | внутренний JSON ленты, только новые страницы | да (и верхняя граница) | да | да | проектов и % найма |
| FL.ru | RSS: вся лента + «Программирование», «Дизайн», «Сайты» | нет | нет | да | нет |
| Freelance.ru | HTML: «Веб-разработка и IT», «ИИ» | да | да | да | нет |
| freelancejob.ru | HTML ленты | да | да | да | нет |
| pchel.net | HTML ленты | в $, в описании | да | нет (берётся время обнаружения) | нет |
| Telegram-каналы | веб-превью `t.me/s/<канал>`, последние ~20 постов | нет | нет | да | нет |

Список Telegram-каналов задаётся в `settings.json` или командой `/channel`.

Не подключены:
- **Weblancer, YouDo, Freelancehunt** — блокируют автоматический доступ (HTTP 403).
- **Workzilla, Profi.ru** — заказы видны только после входа в аккаунт.
- **Хабр Фриланс** — закрыт (HTTP 410).

Источники FL.ru и Freelance.ru в `sources/` взяты из
[IsWake77/FreelanceParser](https://github.com/IsWake77/FreelanceParser).

## Ниши

Правила ниш — словарь `NICHES` в `notify.py`. У каждой ниши есть три списка:
- **strong** — слова, которых достаточно в любом месте заказа, включая описание;
- **weak** — слова пошире, их ищем только в заголовке и рубрике;
- **exclude** — слова в заголовке, при которых ниша не срабатывает.

Кроме слов, нишу задают рубрики площадок: словарь `NICHE_CATEGORIES`.

| Тег | Что ловит |
|---|---|
| `[ИИ]` | ИИ-агенты и ассистенты, RAG, Dify, n8n, Claude, Codex, Cursor, вайбкодинг, подключение API моделей. Генерация картинок, видео и текстов исключена |
| `[Данные]` | парсинг, сбор баз, Excel и Google Таблицы, обработка и анализ данных |
| `[3D]` | Blender, low-poly, Unity, Unreal, Godot, ретопология, риг, текстуры, level design |
| `[Игры]` | моды, игровые серверы, Roblox, GMod/GLua, MTA, Lua-скрипты, рубрика «Игры» |
| `[Приложения]` | Flutter, Android, iOS, публикация в Google Play и RuStore. Тестирование исключено |
| `[Маркетплейсы]` | автоматизация для продавцов WB и Ozon: API, массовое заполнение и перенос карточек, отчёты. Инфографика исключена |
| `[★]` | сработал белый список (см. `/allow`) |

Общие исключения для всех ниш — список `EXCLUDE`: лайки и отзывы, лидогенерация, обзвоны,
рассылки, SEO и ссылки, набор текста, 1С, чертежи, интерьеры и т.п.

## Уведомление

```
[ИИ] Настроить ИИ-агента на сайт

🕒 22.09 13:05 МСК (12 мин назад) · kwork · Скрипты, боты и mini apps
👤 заказчик: проектов 35, нанимает в 90%
🎯 похоже на твои 👍: 72%

https://kwork.ru/projects/…
[👍 интересно] [👎 мимо]
```

Каких данных нет у площадки, тех строк нет и в сообщении. Строка 🎯 появляется, когда
накопится достаточно оценок.

## Управление из Telegram

### Кнопки
- **👍 интересно / 👎 мимо** — оценка заказа. После нажатия кнопки сменяются на «отмечено».
- Оценки хранятся в таблице `feedback` и нужны для двух вещей:
  - по ним считается 🎯;
  - по ним можно вручную уточнять правила ниш.

### Команды

| Команда | Что делает |
|---|---|
| `/ban слово` | не присылать заказы с этим словом (чёрный список) |
| `/unban слово` | убрать слово из чёрного списка |
| `/allow слово` | присылать заказы с этим словом всегда, даже вне ниш (белый список) |
| `/unallow слово` | убрать слово из белого списка |
| `/minprice 3000` | не присылать заказы дешевле 3000 ₽; `0` — выключить. Заказы без бюджета проходят |
| `/hide 20` | прятать заказы с 🎯 ниже 20%; `0` — выключить |
| `/off Данные`, `/on Данные` | выключить или включить нишу (регистр не важен) |
| `/channel add имя`, `/channel del имя` | добавить или убрать Telegram-канал (без `@`) |
| `/rules` | показать текущие настройки |
| `/stats` | сколько поставлено 👍 и 👎 |
| любое другое сообщение с `/` | справка |

Слова ищутся по началу слова и без учёта регистра: `/ban вордпресс` отсечёт и «вордпресса».

**Когда бот отвечает.** Сразу, если в этот момент идёт запуск на GitHub. Если запуск ещё не
начался, ответ придёт, когда он стартует, обычно в пределах 10–20 минут. Сообщения не теряются:
Telegram хранит их до 24 часов.

### Оценка 🎯
Считается наивным байесовским классификатором (класс `Scorer` в `notify.py`):
- **на чём учится:** на словах из заголовка, рубрики и начала описания заказов, которые ты
  оценил. От каждого слова берутся первые 6 букв, это грубая замена стеммингу;
- **когда включается:** когда есть хотя бы 10 👍 и 10 👎 (константа `MIN_LABELS`);
- **что показывает:** вероятность, что заказ тебе понравится;
- **для заказов из белого списка** не считается.

## settings.json

```json
{
  "blacklist": [],
  "whitelist": [],
  "min_price": 0,
  "hide_below_score": 0,
  "niches_off": [],
  "telegram_channels": ["devjobs", "cgfreelance", "freelancetaverna"]
}
```

| Поле | Значение |
|---|---|
| `blacklist` | слова, при которых заказ не присылается |
| `whitelist` | слова, при которых заказ присылается всегда |
| `min_price` | минимальный бюджет в рублях |
| `hide_below_score` | порог 🎯 в процентах, ниже которого заказ прячется |
| `niches_off` | выключенные ниши |
| `telegram_channels` | каналы без `@` |

Файл меняют команды бота, но его можно править и руками прямо на GitHub. Изменения
подхватятся со следующего запуска.

## Как фильтр решает, присылать ли заказ

Функция `classify()` в `notify.py` проверяет по порядку:

1. Есть слово из белого списка → **прислать** с тегом `[★]`.
2. Есть слово из чёрного списка или из общих исключений `EXCLUDE` → **не присылать**.
3. Бюджет известен и меньше `min_price` → **не присылать**.
4. Найти ниши по словам (`NICHES`) и рубрикам (`NICHE_CATEGORIES`), убрать выключенные.
   Ни одной не осталось → **не присылать**.
5. Посчитать 🎯. Если оценка включена и ниже `hide_below_score` → **не присылать**.

## Установка

Нужны аккаунт GitHub и бот в Telegram.

1. **Бот.** В [@BotFather](https://t.me/BotFather) отправить `/newbot` и получить токен.
   Написать своему боту любое сообщение.
2. **chat_id.** Локально выполнить `python3 notify.py --setup <токен>`. Скрипт найдёт твой
   chat_id, сохранит его в `tg.json` и пришлёт тестовое сообщение.
3. **Репозиторий.** Публичный: для публичных репозиториев минуты Actions бесплатны без
   ограничений. Запуск раз в 10 минут по ~9 минут не влезает в бесплатные 2000 минут
   приватного репозитория.
4. **Секреты.** Settings → Secrets and variables → Actions:
   - `TG_TOKEN` — токен бота;
   - `TG_CHAT_ID` — chat_id из `tg.json`.

   Или через `gh`:
   ```bash
   gh secret set TG_TOKEN
   gh secret set TG_CHAT_ID
   ```
5. **Первый запуск.** Вкладка Actions → workflow «notify» → «Run workflow». Дальше работает
   по расписанию.

**Остановить:** Actions → «notify» → «Disable workflow».

**Если `api.telegram.org` недоступен напрямую** (для локального запуска): добавить в `tg.json`
поле `"proxy": "http://127.0.0.1:7890"`. Прокси socks5 стандартная библиотека не умеет.

## Локальный запуск

Нужен только Python 3.9+, внешних зависимостей нет.

```bash
python3 notify.py --setup <токен>   # подключить бота
python3 notify.py --test 5          # прислать 5 последних подходящих заказов из базы
python3 notify.py                   # один проход с уведомлениями
python3 notify.py --loop 540        # 9 минут: площадки раз в 3 мин, команды сразу

python3 collect.py                  # собрать заказы без уведомлений
python3 collect.py --full           # пройти всю ленту Kwork (~50 страниц, ~12 минут)
python3 collect.py --no-kwork       # всё, кроме Kwork
```

**Не запускай `notify.py` локально, пока работает GitHub Actions.**
- Уведомления будут приходить дважды.
- Локальный запуск заберёт команды из Telegram, и бот на GitHub их уже не увидит.

**macOS.** Python с python.org не видит системные сертификаты. `collect.py` сам подставляет
`/etc/ssl/cert.pem`.

## База данных

`market.db` — SQLite. Свежая копия в репозитории обновляется раз в 6 часов.

| Таблица | Содержимое |
|---|---|
| `orders` | все заказы: `source`, `id`, `url`, `title`, `description`, `category`, `price`, `price_max`, `days`, `created`, `expires`, `buyer_orders`, `buyer_hired_pct`, `responses`, `views`, `first_seen`, `last_seen` |
| `snapshots` | история откликов и просмотров: `source`, `id`, `ts`, `responses`, `views`. Видно, как быстро растёт конкуренция |
| `feedback` | оценки из Telegram: `source`, `id`, `label` (1 = 👍, −1 = 👎), `ts` |
| `kv` | служебное, например позиция чтения обновлений Telegram |

Примеры запросов:

```sql
-- медианы по рубрикам Kwork считать удобнее в Python, а так — средние
select category, count(*) n, round(avg(price)) price, round(avg(responses), 1) resp
from orders where source = 'kwork' group by category order by n desc;

-- заказы, которые ты отметил 👍
select o.title, o.price, o.url from feedback f
join orders o using (source, id) where f.label = 1;

-- сколько новых заказов в день по площадкам
select substr(first_seen, 1, 10) day, source, count(*) from orders group by 1, 2;
```

Когда поле `created` заполнено, его формат зависит от площадки:
- Kwork — `YYYY-MM-DD HH:MM:SS` по Москве;
- FL.ru — RFC 822 в GMT;
- Freelance.ru — `DD.MM.YYYY HH:MM`;
- остальные — ISO 8601.

Разбирает все эти форматы `parse_created()` в `notify.py`.

## Файлы проекта

| Файл | Назначение |
|---|---|
| `notify.py` | ниши и фильтр, оценка 🎯, сообщения, команды и кнопки Telegram, режим `--loop` |
| `collect.py` | сбор с площадок, схема базы, сохранение, `settings.json` |
| `sources/base.py` | HTTP-клиент на стандартной библиотеке (куки, ретраи) |
| `sources/flru.py`, `sources/freelanceru.py` | FL.ru и Freelance.ru |
| `sources/extra.py` | pchel.net, freelancejob.ru, Telegram-каналы |
| `settings.json` | настройки фильтра (меняются командами бота) |
| `market.db` | база заказов, оценок и снимков |
| `kwork_categories.json` | кэш названий рубрик Kwork (обновляется раз в неделю) |
| `.github/workflows/notify.yml` | расписание GitHub Actions |
| `tg.json` | токен и chat_id для локального запуска, в git не попадает |

**Как добавить площадку:**
1. Написать в `sources/extra.py` функцию, которая возвращает список словарей с полями
   `source`, `id`, `url`, `title`, `description`, `category`, `price`, `responses`, `created`.
2. Добавить её в `all_sources()` в `collect.py`.

Первый проход по новой площадке пройдёт без уведомлений.

## Ограничения

- **Задержки GitHub.** Расписание Actions не точное: запуски сдвигаются на 5–20 минут,
  а на новом репозитории могут начаться не сразу. Пока запуска нет, бот не отвечает.
- **Лимиты Kwork.** Kwork отвечает 403 на частые запросы. Между страницами пауза 12 с, после
  403 — пауза 2 минуты и одна повторная попытка. Обычный проход берёт только новые страницы.
- **FL.ru** в RSS не отдаёт бюджет и отклики.
- **pchel.net** не показывает дату, бюджет у него в долларах.
- **Telegram-каналы** публикуют много вакансий на полную занятость, их отсеивают фильтры ниш.
- **Потеря кэша.** Если кэш Actions пропадёт, база восстановится из последнего коммита, а
  первый проход будет тихим.
- **Правила ниш подобраны по заказам за 1–2 дня** в сентябре 2026. Их стоит пересматривать
  по накопленным 👍/👎.
